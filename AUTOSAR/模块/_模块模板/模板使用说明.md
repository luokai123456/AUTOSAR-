# AUTOSAR 模块模板使用说明

> 本目录是新建模块的**唯一模板来源**。以后新增 EcuM、Com、CanSM 等模块时：整体复制 `_模块模板` → 改名为 `<模块名>` → 按本说明替换占位符。

## 1. 复制与命名

1. 复制整个 `模块/_模块模板/` 为 `模块/<模块名>/`；
2. 把 `模块总览模板.md` 改名为 `<模块名>.md`（L1 唯一入口，如 `CanNm.md`、`BswM.md`）；
3. 所有模板文件名去掉“模板”二字，按 `<模块名>_<内容>.md` 命名；
4. 把文中 `<模块名>` 全部替换为真实模块名，大小写与 AUTOSAR 官方一致；
5. 删除本说明、示例内容、未使用的 07 目录。

## 2. 模块目录结构（9 项交付物）

```text
<模块名>/
├─ <模块名>.md                         ← L1 模块总览（唯一入口）
├─ <模块名>_问题排查记录.md             ← Q-xxx 历史问题（非标准问题）
├─ 01_官方文件/                        ← 官方 PDF + <模块名>_来源清单.md
├─ 02_学习总结/
│  ├─ <模块名>_模块作用与架构定位.md
│  ├─ <模块名>_DaVinci配置项.md
│  ├─ <模块名>_一页纸复盘.md
│  └─ <模块名>_<特性>说明.md（可选：专题深入，如 BusLoadReduction）
├─ 03_调用逻辑/
│  ├─ <模块名>_调用逻辑总览.md          ← L2 Hub
│  ├─ <模块名>_D1_...md ~ Dn            ← 方向主线
│  ├─ <模块名>_函数调用层级.md
│  ├─ <模块名>_全局变量说明.md
│  └─ <模块名>_状态转换表.md
├─ 04_MainFunction流程/
│  └─ <模块名>_MainFunction调用逻辑.md
├─ 05_标准表格/
│  ├─ <模块名>_AUTOSAR标准需求表_R21-11.md
│  ├─ <模块名>_配置参数表_R21-11.md
│  └─ <模块名>_需求追溯与覆盖度.md
├─ 06_问题排查/
│  ├─ <模块名>_快速问题定位.md
```

> 不再使用 `99_参考资料`；参考资料并入 `01_官方文件` 或对应主题文档。

## 3. 命名规范

| 类型 | 命名 |
|---|---|
| L1 模块总览 | `<模块名>.md`（固定） |
| 方向主线 | `<模块名>_D<n>_<方向名>.md` |
| Hub/说明 | `<模块名>_<内容>.md` |
| 需求表 | `<模块名>_AUTOSAR标准需求表_R21-11.md` |
| 配置表 | `<模块名>_配置参数表_R21-11.md` |
| 追溯 | `<模块名>_需求追溯与覆盖度.md` |
| 问题记录 | `<模块名>_问题排查记录.md` |
| 06 手册 | `<模块名>_快速问题定位.md`、`<模块名>_时间类问题排查.md` |
| 07 清单 | `<模块名>_非标准实现.md` |

- 文件名全局唯一，避免 Obsidian 双链歧义；
- 需求号、函数名、变量名**保持官方/代码原文**，不翻译。

## 4. 链接规则（Obsidian 图谱必须呈树形）

1. **只允许上级 ↔ 下级双链**；
2. L3 文档（D1~Dn、函数层级、全局变量、状态表）只链 L2 Hub；L2 Hub 只链 L1；L1 链 L0；
3. 同级文档之间**禁止互链**，用纯文本“见 D3/D4”；关系图用 Mermaid（Mermaid 不产生图谱边）；
4. 每篇顶部必须有 `> [!info] 导航 > 上级：...`；
5. 需求号、变量名、函数名在正文中优先用纯文本；跨文档锚点只允许上级→下级；
6. 外部代码跳转用 `vscode://file/...:line`（不进入图谱），并保留文件入口兜底。

## 5. 各文件内容要求

| 文件 | 必须包含 |
|---|---|
| L1 模块总览 | 一句话定位、版本/实现基线、5 大主题入口、L2→L3 层次、9 项交付物勾选、更新记录 |
| 来源清单 | 官方 PDF（名称/类型/版本/页数/URL/日期）+ 本地生成代码清单（路径/版本/文件） |
| 模块作用与架构定位 | 在 AUTOSAR 分层中的位置、上下依赖、核心机制、状态/定时器/数据流、实现基线 |
| 专题说明（可选） | 某个复杂特性单独展开（如降载/PNC/定时器），避免主文档过长 |
| DaVinci 配置项 | 容器 → 参数 → 作用、依赖配置、常见坑、生成代码检查点 |
| 一页纸复盘 | 可复述版：作用、5 个关键点、常见问题、面试/评审能讲清的版本 |
| 调用逻辑总览 | D1~Dn 方向表、每方向触发/入口/输出、函数层级与全局变量入口、阅读顺序 |
| D<n> 方向文档 | 触发 → 调用链（函数+上下文）→ 状态/数据变化 → 输出 → 需求号；Vendor/项目差异用纯文本标注 |
| 函数调用层级 | 实际函数名+行号、上下文、可重入性、L1/L2/L3 调用树、与旧逻辑名差异 |
| 全局变量说明 | 配置（ROM）/运行状态（RAM）/静态变量，类型、维度、读写宏、写者/读者、旧名对照、实现差异 |
| 状态转换表 | 状态清单、T-xx 转换表（当前/事件/下一状态/动作/需求号）、Mermaid、代码宏对应 |
| MainFunction 调用逻辑 | 调度/周期、实际执行顺序、分步解析、伪代码、**深度 3 代码注释拆解**、函数作用、全局变量高亮、代码跳转、配置影响、排障 |
| 标准需求表 | 按需求号百位分组锚点，中文可执行描述、API/配置/章节、ECUC 表、SRS→SWS 追溯、覆盖度统计 |
| 配置参数表 | ECUC 容器/参数、类型、默认/约束、父容器、作用、本项目实例值（tick/值） |
| 需求追溯与覆盖度 | RS/SRS→SWS 映射、覆盖率、裁剪/差异说明 |
| 问题排查记录 | Q-xxx 总表 + 详细记录（现象/复现/环境/排查过程/根因/解决/回归/关联） |
| 快速问题定位 | 第一时间看什么（P0~P5）、现象→首查、观测变量、分层定位、断点/抓包、配置坑、30 分钟流程 |
| 时间类问题排查 | 时间基准（tick/周期）、理论窗口、上下电/状态转换/首帧/定时器、测量手段、超时排查 |
| 非标准实现 | NS-xxx 清单：名称、开关/Hook、代码位置、与 SWS 差异、风险、必测场景、移植建议 |

## 6. 代码实现基线要求

每篇涉及实现的文档必须写清：

- 供应商/工具链版本（如 NeuSAR 3.14.0）与 AUTOSAR 版本（如 4.2.2）；
- 生成代码路径（相对工作区）；
- 实际函数名/行号、实际变量名（不要只写标准概念名）；
- 时间参数单位：**tick（主函数周期数）** 还是 ms，并给换算公式；
- 厂商扩展/项目 Hook 单独列出（进入 07）。

## 8. 常见错误

1. 同级 D 文档互链 → 图谱交叉；改为纯文本/Mermaid；
2. 只写标准概念名、不写实际变量 → 排查找不到；
3. 把 tick 当 ms → 时间判断全错；
4. 直接复制模板占位符未替换 → 链接失效；
5. 07 与 06 内容重复 → 06 只做定位，07 记录非标准实现；
6. 忘记更新 L1 入口 → 新文档在图上孤立。

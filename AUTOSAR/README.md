## 二、每个模块的 7 项交付物（固定要求）

| 序号 | 交付物 | 存放位置 | 说明 |
|---|---|---|---|
| 1 | 模块文件夹 + 子文件夹 + **模块总览** | `模块/<模块名>/`、`<模块名>.md` | L1 唯一入口；模块简称大小写与 AUTOSAR 一致 |
| 2 | AUTOSAR 官方文档（PDF） | `01_官方文件/` | SWS 为主，附 SRS/EXP/TR；同目录 `<模块名>_来源清单.md` 记录版本/URL/页数 |
| 3 | 模块总结 | `02_学习总结/` | ①模块在 AUTOSAR 架构中的作用与位置；②DaVinci 配置项及作用 |
| 4 | **调用逻辑** | `03_调用逻辑/` | ①按"大方向"拆分调用主线（如主动唤醒/被动唤醒/主状态转移…）；②函数调用层级从上到下；③全局变量作用；④状态转换表 |
| 5 | **MainFunction 调用逻辑** | `04_MainFunction流程/` | 结合第 4 项的方向，生成主函数被调度后的调用顺序与实现功能 |
| 6 | **AUTOSAR 标准需求表** | `05_标准表格/` | 中文整理官方需求，**按 AUTOSAR 需求号**排序成表（SWS_/SRS_/ECUC_） |
| 7 | **问题排查记录** | `问题排查记录.md` | 只记**非 AUTOSAR 标准问题**（工具/版本/集成/硬件/项目定制/供应商差异），持续追加 |

## 三、第 4 项：调用逻辑怎么组织（重点）

### 3.1 先划分"大的方向"，一个方向一条主线

不要一上来画全量关系图，先按模块的业务主线拆分。以 **CanNm** 为例：

| 方向编号 | 方向名称 | 这条线回答的问题 |
|---|---|---|
| D1 | 主动唤醒调用逻辑 | ECU 主动请求网络（`CanNm_NetworkRequest`）后，从 API 到状态机、发送、回调的完整链路 |
| D2 | 被动唤醒调用逻辑 | 总线上先有 NM 帧（`CanNm_RxIndication` / `CanNm_PassiveStartUp`）时，如何进入网络 |
| D3 | 主状态转移逻辑 | 5 个状态之间的跃迁条件与执行动作（总线睡眠/准备睡眠/重复报文/正常运行/就绪睡眠） |
| D4 | 状态转换表 | 状态 × 事件 → 下一状态、执行动作、关联需求号 |
| D5 | 周期发送与降载调用逻辑 | 主函数里周期发送、立即发送、降载重装、PN shutdown 的链路 |
| D6 | 通信控制调用逻辑 | 诊断 0x28 → `CanNm_Disable/EnableCommunication` 的链路与定时器影响 |
| D7 | 扩展特性调用逻辑 | PNC、CarWakeup、远程睡眠、协调器同步、用户数据、发送错误处理 |
| … | 按模块补充 | 如多通道协调、总线同步 |

> 每个模块的方向数不固定：先把 SWS 的功能章节（第 7 章）读成"几条业务主线"，再落成文件。

### 3.2 每条主线的固定写法

1. **触发**：谁在什么上下文（任务/中断/API 调用）发起；
2. **调用链**：从上到下逐层列出函数（入口 → 中间处理 → 驱动/输出），标注文件与上下文；
3. **状态/数据变化**：进入/离开什么状态、哪些定时器/变量被改；
4. **输出**：调用了谁（`CanIf_Transmit`、`Nm_*` 回调等）；
5. **依据**：关联的 SWS 需求号（与第 6 项标准需求表互相引用）。

### 3.3 函数调用层级（从上到下）

- 顶层：调度入口（`Xxx_MainFunction`）、对外 API、回调（Rx/TxConfirmation/中断）；
- 中层：状态机处理、定时器处理、PDU 组装/解析、动作分发；
- 底层：驱动/接口调用（CanIf、PduR、Det…）。
- 用缩进树或 Mermaid 表示，**同一层按调用先后排列**，并标注执行上下文。

### 3.4 全局变量说明

每个模块在 `03_调用逻辑/` 里单独说明模块级变量（含配置结构体实例）：

| 列 | 说明 |
|---|---|
| 变量/结构 | 生成代码中的名字（如 `CanNm_ChannelConfig[]`、`CanNm_GlobalState`） |
| 定义位置 | 文件/结构体 |
| 类型 | 类型名 |
| 作用 | 它保存什么、为什么需要 |
| 写者 | 哪个函数/上下文写 |
| 读者 | 谁依赖它 |
| 生命周期 | 初始化/运行/休眠期间的变化 |

### 3.5 状态转换表

- 状态清单：状态名/含义/进入动作/退出动作；
- 转换表：`当前状态 + 触发事件/条件 → 下一状态 + 执行动作 + 需求号`；
- 与代码对应：状态枚举、状态处理函数。

## 四、第 5 项：MainFunction 调用逻辑怎么生成

1. 调度方式：谁调用、周期配置、上下文、是否可重入；
2. 输入：进入主函数前已就绪的数据（接收缓冲、请求标志、定时器）；
3. 处理顺序：**按第 4 项的方向逐段映射**——每个方向在主函数中对应哪一段、什么条件进入；
4. 全局变量在主函数中的读写变化；
5. 输出与回调：发帧、状态回调、错误上报；
6. 伪代码 + 排障点（耗时、周期、时序抖动）。

> 要求：第 5 项必须能"指回"第 4 项的方向编号，不能脱离调用逻辑另写一套。

## 五、第 6 项：AUTOSAR 标准需求表（05_标准表格）

- 文件命名：`<模块名>_AUTOSAR标准需求表_R21-11.md`；
- **全部中文整理**，需求号保留官方原文（如 `SWS_CanNm_00087`）；
- 表格列：需求号 / 中文描述 / 模块行为 / 关联 API 或配置 / 出处章节 / 备注；
- 附加两张表：`SRS → SWS` 追溯表、覆盖度统计（已整理数 / 文档总数）；
- 排序：按需求号数字升序；同类需求（状态机/定时器/发送/接收/配置）可先分组再排序。

## 六、第 7 项：问题排查记录（非标准问题）

### 6.1 边界（很重要）

| 记录到 `<模块名>_问题排查记录.md` | 不记录，归到别处 |
|---|---|
| DaVinci 配置工具异常、生成代码差异 | AUTOSAR 标准行为本身的问题 → `02/03/05` |
| 编译器/链接器/内存布局问题 | 需求理解错误 → `03/05` |
| ECU 硬件/收发器/采样点/终端电阻问题 | 协议时序符合标准但项目参数错误 → `02` DaVinci 配置项 |
| 供应商实现与标准不一致、补丁 | — |
| 项目定制逻辑、OEM 特殊要求 | — |
| 集成顺序、启动时序踩坑 | — |

### 6.2 记录格式

`问题排查记录.md` 固定列：`编号(Q-xxx) / 日期 / 现象 / 环境与版本 / 根因 / 解决或规避 / 状态 / 关联`；
每条问题在文件下方附"详细记录"小节（复现条件、排查过程、回归验证）。**状态**：已解决 / 规避中 / 待确认 / 无法复现。

### 6.3 持续更新

- 每遇到一个新问题追加一条，编号递增，不删除历史；
- 解决了就更新状态与解决方案，保留排查过程（这是最有价值的部分）；
- 与 `02_学习总结` 的配置项、`03_调用逻辑` 的主线互相加链接。

## 七、文档来源与版本策略

官方文档统一从 AUTOSAR 官网下载：`https://www.autosar.org/fileadmin/standards/<版本>/<平台>/`

- `<版本>` 例如 `R21-11`、`R22-11`、`R20-11`、`R4.4.0`
- `<平台>`：`CP` 为 Classic Platform，`AP` 为 Adaptive Platform
- 常用文档类型前缀：
  - `SWS_` Software Specification（软件规范，最核心）
  - `SRS_` Software Requirement Specification（需求）
  - `EXP_` Explanation（解释性说明）
  - `TR_` Technical Report（技术报告）
  - `TPS_` Template/Protocol Specification（模板/协议规范）
  - `PRS_` Protocol Specification（协议规范，如网络管理协议）

**版本基准**：默认以项目实际使用的 AUTOSAR 版本为准；未指定时按 `R21-11 / CP` 下载。每个模块的 `01_官方文件/<模块名>_来源清单.md` 需记录：文件名、文档类型、AUTOSAR 版本、页数、下载 URL、下载日期。

## 八、命名与写作规范

- 文件夹：模块官方简称（大小写与 AUTOSAR 文档一致，如 `BswM` 不写成 `BSWM`）
- 文件：`<模块名>_<内容>_<类型>.md`，例如 `CanNm_主动唤醒调用逻辑.md`
- **Obsidian 双链**：模块内跨文档引用统一用双链（如 `[[CanNm_D1_主动唤醒调用逻辑]]`，不带路径与 `.md`）；文件名必须带模块前缀以保证全库唯一（如 `CanNm_D1_主动唤醒调用逻辑.md`），这样 Obsidian 图谱里能直接看到方向之间的调用关系。
- 图：用 Mermaid 写在 Markdown 里（VS Code / Typora 可直接渲染），必要时再导出 PNG 放同目录
- 每份总结开头写：`适用版本 / 依据文档 / 最后更新日期`
- 引用官方文档时标注章节号；调用逻辑与需求表互相引用需求号
- 问题排查编号 `Q-001` 起；需求表按官方需求号

## 九、学习一个模块的标准流程

1. **建目录**：复制 `模块/_模块模板` 为 `模块/<模块名>`，把模块总览模板改名为 `<模块名>.md` 并填写
2. **下文档**：SWS（必需）+ SRS/EXP/TR（选需），写 `01_官方文件/<模块名>_来源清单.md`
3. **写总结**：模块作用与架构定位 → DaVinci 配置项（Container → Parameter → 作用）
4. **拆调用逻辑**：按第 3 节的方法划分大方向 → 每个方向的调用链 → 函数层级 → 全局变量 → 状态转换表
5. **生成 MainFunction 调用逻辑**：按第 4 节规则，把方向映射到主函数处理段
6. **整理标准需求表**：按需求号中文整理，建 SRS→SWS 追溯与覆盖度统计
7. **记问题排查**：把非标准问题按 Q-xxx 追加到 `问题排查记录.md`
8. **复盘**：`02_学习总结` 里写一页"面试/工作可复述版"

> 下载文档可用脚本：`python _工具/autosar_docs.py --module BswM --docs AUTOSAR_SWS_BSWModeManager.pdf`
> （默认从 autosar.org R21-11/CP 下载到 `模块/<模块>/01_官方文件/`，并自动提取文本到 `../.tools/tmp/` 便于检索；
> 换版本用 `--release R22-11`，换平台用 `--platform AP`。）
>
> **流程管理技能（通用）**：`_技能/autosar-module-workflow/SKILL.md` —— 维护任意模块《<模块名>标准化流程.xlsx》的通用技能（15 个 Sheet 含甘特视图、ID/状态规则、更新流程、校验/实例化/刷新甘特脚本、已知坑）。新模块（EcuM/Com 等）用 `scripts/instantiate_workbook.py` 一键实例化；修改工作簿前后运行 `scripts/validate_workbook.py` 校验。

## 十、引用与导航规范（Obsidian，v3）

### 10.1 四层引用结构

| 层级 | 文件 | 职责 |
|---|---|---|
| L0 | `00_总览/AUTOSAR.md` | 整库唯一总入口：AUTOSAR 总体、分层图、模块地图、主题索引 |
| L1 | `模块/<模块>/<模块>.md` | 模块唯一入口：5 个主题（学习总结/调用逻辑/主函数/标准表格/问题排查） |
| L2 | `03_调用逻辑/<模块>_调用逻辑总览.md` 等 | 主题 Hub：方向清单 + 阅读顺序 |
| L3 | `<模块>_D<n>_*.md`、需求表分组等 | 具体方向/表格，只有"上级 + 依赖 + 依据" |

### 10.2 三种链接，禁止第四种

1. **导航链接**（顶部 `> [!info] 导航`）：只放直属上级、必要的同级入口；
2. **依赖链接**（正文）："读这段前必须先看哪篇"，不超过 2–3 条；
3. **依据链接**（正文/底部）：需求号、状态表编号、配置参数表。

> 规则：**非 Hub 文件**链接总数 ≤ 8 条（导航 1–4 + 依赖 2–3 + 依据 1–2）；**Hub 文件**（L0/L1/L2 总览、MainFunction 映射页、需求表）不限；禁止"把所有相关文档列一遍"的关联清单（旧版已删除）。同一事实只在一处展开，其他文档用链接 + 一句话。

### 10.3 锚点引用

- 状态转换：`[[CanNm_D4_状态转换表#从 Normal Operation 出发]]`（D4 按源状态分小节）；
- 需求号：`[[CanNm_AUTOSAR标准需求表_R21-11#SWS_CanNm_001xx|SWS_CanNm_00104]]`（按需求号百位分组）；
- 函数层级/配置参数同理使用标题锚点。

### 10.4 文件命名与图谱

- L0 固定 `AUTOSAR.md`；L1 固定 `<模块名>.md`（如 `CanNm.md`），别名可写 `aliases`；
- 其他文件一律 `<模块名>_<内容>.md`，保证 Obsidian 双链全局唯一；
- Canvas：`00_总览/AUTOSAR_架构地图.canvas`（L0→L1→主题），模块内可加 `<模块>_调用逻辑地图.canvas`；
- 图谱建议：按文件夹设颜色组（00_总览红 / 02_学习总结蓝 / 03_调用逻辑绿 / 04 橙 / 05 紫 / 问题排查黄），过滤 `01_官方文件`；
- 验收：任意文档 ≤3 次点击可达、每篇顶部有"上级"、需求号可跳分组、图谱呈放射层级。

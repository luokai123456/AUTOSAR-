# 工作簿列定义（通用，<模块名> 占位）

> 依据 `CANNM标准化流程.xlsx`（V0.03，15 个 Sheet）。新模块实例化后结构不变。

## 3-开发计划（核心）

标题行 1；表头行 2；数据从第 3 行起；冻结 `D3`；筛选；状态列 `N` 下拉。

| 列 | 字段 | 类型/取值 |
|---|---|---|
| A | 阶段 | P0~P6 |
| B | WBS | P0.1、P1.1、G1… |
| C | 任务项 | 文本（<模块名> 相关） |
| D | 交付物ID | REQ-/CFG-/LOG-/DES-/CAPL-/G… |
| E | 交付物 | 文本 |
| F | 验收标准 | 可判定的标准 |
| G | 前置依赖 | WBS 编号或“-” |
| H | 工期(天) | 整数 |
| I/J | 计划开始/完成 | 日期（甘特依赖） |
| K/L | 实际开始/完成 | 日期或空 |
| M | 进度 | 0~1，显示 0% |
| N | 状态 | 计划/进行中/待评审/完成/阻塞/挂起 |
| O | 责任人 | 文本 |
| P | 关联需求/差异 | 需求号/差异号/空 |
| Q | 风险与备注 | 文本 |

## 4-需求追溯矩阵

字段：需求号（`SWS_<模块名>_xxxxx`）/ 章节 / 中文摘要 / 适用性（适用、裁剪、差异、待确认）/ 实现位置 / 配置项（`ECUC_<模块名>_xxxxx`）/ 测试用例 / 状态 / 备注。

规则：裁剪/差异必须在备注写依据；差异关联 `5-差异台账`。

## 5-差异台账

DIF-xxx / 类型（四分类）/ 标准依据 / 差异描述 / 来源 / 影响分析 / 处置 / 责任人 / 状态 / 关联需求 / 验证方式。

## 6-测试用例与CAPL

TC-xxx / 场景 / 前置条件 / 步骤 / 预期结果 / 关联需求 / CAPL 脚本 / 执行结果 / 状态（计划/执行中/通过/失败/阻塞）。

覆盖：状态迁移（对照模块 D4 状态转换表 T-xx）、定时器边界、异常路径、多节点一致性。

## 7-问题台账

Q-xxx / 日期 / 现象 / 环境版本 / 根因 / 解决或规避 / 状态（已解决/规避中/待确认/无法复现）/ 关联文档。

## 8-评审记录

G0~G6 / 日期 / 参与人 / 检查项 / 结论（通过/有条件通过/不通过/待评审）/ 遗留问题 / 关闭期限。

## 9-变更记录

CR-xxx / 日期 / 类型 / 变更内容 / 影响分析 / 审批 / 关联CR或需求。

## 10-基线清单

BL-xxx / 日期 / AUTOSAR版本 / 工具版本 / BSWMD-ECUC版本 / 代码分支标签 / 文档版本 / 脚本版本 / 备注。

## 11-能力分析

能力项 / 要求等级(0~4) / 当前等级 / 差距 / 学习动作 / 关联 WBS / 验收证据。

## 12-术语与参考

类别 / 名称或编号 / 说明。需包含 SWS/SRS/PRS/EXP 编号、工具版本、ID 前缀、Obsidian 工作区路径。

## 13-甘特视图

由 `3-开发计划` 自动生成：
- 列 A~G：WBS、任务项、阶段、计划开始、计划完成、工期、进度；
- 列 H 起：按周列（周起始日期，格式 m/d）；
- 单元格填充按阶段着色；评审门行在完成周显示 `◆`；
- 修改计划日期后运行 `scripts/refresh_gantt.py` 刷新。
